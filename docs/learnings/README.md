# Learnings

Short notes on what the team learned the hard way: spike outcomes, bugs with non-obvious causes, "we tried X and it failed", tool and vendor gotchas.

Decisions go in [`../decisions/`](../decisions/README.md) as ADRs. Learnings are the evidence and experience behind them, and they're allowed to be small and informal.

## How to add one

1. Copy `TEMPLATE.md` to `YYYY-MM-DD-short-slug.md`.
2. Fill it in. Five lines is fine.
3. Add a row to the index below, newest first.

Close every spike with a learning. If a learning changes a decision, link it from the ADR or propose a new one with `/propose-adr`.
